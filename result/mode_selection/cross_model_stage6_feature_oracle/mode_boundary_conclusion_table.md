# 跨模型模式边界结论表

本表用于支撑论文/汇报中的模式选择叙事：不再把 FWMS 讲成“最低时延选择器”，而是讲成“可行性约束 + 任务特征驱动的模式边界判别”。`Oracle-Min-Latency` 只作为预测最小时延上界，用于展示如果完整评估所有模式，理论上最短时延会落在哪个模式。

| 模型 | 可行性边界 | Oracle 低时延上界 | FWMS-Feature 选择分布 | 平均特征 | 论文可写结论 |
|---|---|---|---|---|---|
| YOLO | PMP、GS-Only、Sat-Only、CDP 全部可行 | CDP 42/42，平均 1995.62 ms | PMP 42/42，平均 6597.55 ms | η=0.60，ρ=0.04，U=0.51 | CDP 在可行时具有明显低时延优势；当前等权 FWMS 更保守，偏向高带宽路径上的 PMP。 |
| ResNet101 | PMP、GS-Only、Sat-Only、CDP 全部可行 | CDP 42/42，平均 453.03 ms | PMP 39/42，CDP 3/42，平均 1800.20 ms | η=1.82，ρ=0.04，U=0.25 | 中等规模模型在 CDP 可行时仍表现出强并行收益；FWMS-Feature 可展示边界判别，但等权参数仍需校准。 |
| VGG19 | PMP、GS-Only 可行；Sat-Only、CDP 不可行 | GS-Only 29/42，PMP 13/42，平均 1343.92 ms | PMP 42/42，平均 1747.12 ms | η=4.62，ρ=0.00，U=0.03 | 完整模型无法放入可见 worker 时，CDP 失效；PMP/GS-Only 成为保底模式，体现模式选择的稳定性价值。 |
| ViT-Huge | PMP、GS-Only 可行；Sat-Only、CDP 不可行 | GS-Only 42/42，平均 1627.23 ms | PMP 42/42，平均 2378.16 ms | η=2.18，ρ=0.00，U=0.16 | 大模型在当前卫星内存条件下不适合 CDP/Sat-Only；若只考虑低时延且 GS 链路可用，GS-Only 最优，PMP 是星上协作保底。 |
| Swin-Base | PMP、GS-Only、Sat-Only、CDP 全部可行 | CDP 42/42，平均 482.25 ms | PMP 39/42，CDP 3/42，平均 1753.22 ms | η=1.33，ρ=0.00，U=0.28 | CDP 可行时低时延优势稳定；FWMS-Feature 需要避免被高链路带宽项过度拉向 PMP。 |

## 适用边界总结

| 模式 | 更适合的任务/场景 | 不适合的任务/场景 |
|---|---|---|
| CDP | Batch 较大、完整模型能放进多颗 worker、需要低时延、允许多星并行能耗开销 | 完整模型超过 worker 内存、可见 worker 数不足、能耗预算非常紧 |
| PMP | 完整模型难以被单星/多 worker 完整容纳，但可以按层切分；需要星上协作保底；存在中间特征压缩收益 | CDP 可行且 batch 较大时，纯时延通常不占优 |
| GS-Only | GS 算力明显强、输入数据不大、GS 链路条件好、大模型不适合上星 | 星地链路差、需要减少对地面站依赖、输入数据极大 |
| Sat-Only | 单颗卫星内存足够且计算能力强，任务较小，想避免多跳协作开销 | 大模型或高 batch 导致单星内存不足；单星算力弱 |
| FWMS-Feature | 作为可行性与任务特征边界判别器，避免固定模式在不同模型/资源条件下失效 | 不应单独宣称为最低时延 Oracle；等权版本需要校准后再作为性能最优选择器 |

## 当前最稳的论文叙事

1. 固定模式不是总可行：VGG19 和 ViT-Huge 下 CDP/Sat-Only 完全不可行。
2. CDP 可行时通常是低时延上界：YOLO、ResNet101、Swin-Base 下 Oracle 全部选择 CDP。
3. PMP 的价值不是在所有场景下打败 CDP，而是在大模型/内存压力/星上协作需求下提供可行保底。
4. FWMS 的价值是根据可行性和特征边界在 PMP/CDP/GS 等模式间切换，提升系统稳定性和适用范围。
